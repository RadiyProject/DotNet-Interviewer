# Финальная проверка решений раунда

Кнопка «Получить сводку Codex CLI» сначала последовательно проверяет каждый сохранённый практический артефакт, затем формирует общую сводку. Отдельные результаты, состояние запросов и снимки сохраняются на сервере. Повтор после сбоя продолжает незавершённые проверки. Общая сводка не принимается, пока не готовы все отдельные проверки и не перечислены все их идентификаторы.

## Что включается

- Новые попытки заданий выбранного, уже начатого раунда автоматически связываются с ним при старте, проверке или отправке. Каждая попытка получает отдельный разбор.
- Для незавершённой попытки используется последний сохранённый на сервере черновик. Несохранённые изменения браузера в отчёт не входят.
- Все разные версии, явно показанные голосовому интервьюеру, сохраняются для финального разбора. Ограничение последних пяти версий относится только к текущему голосовому контексту.
- Старые решения вне раунда добавляются исключительно кнопкой «Приложить результат». Одинаковая задача сама по себе не является основанием включать старую попытку.
- Теория остаётся частью общего интервью. Отдельный разбор решений предназначен для C#, SQL, письменного code review и архитектуры.

При завершении раунда или его дедлайне набор решений и их сохранённое содержимое фиксируются. Последующая работа с задачей не изменяет этот набор. Для старых завершённых раундов используются только доступные приложенные попытки и сохранённые показанные версии: восстановить удалённые ранее версии невозможно.

## Проверки и качество

Функциональные проверки выполняет обычный исполнитель задач. Codex получает исходник и сохранённый результат именно соответствующей версии. Изменение кода после пробного запуска не переносит на него успешный результат предыдущего кода. Если тест ещё выполнялся на момент окончания раунда, в снимке остаётся незавершённый статус; это не успешная проверка. Codex сам не компилирует и не запускает код.

По каждому артефакту оцениваются контракт и крайние случаи, качество и сопровождаемость, безопасность в пределах задания, сложность, сильные стороны и необходимые улучшения. Для письменного ревью оцениваются замечания кандидата по исходному фрагменту, для архитектуры — аргументация и компромиссы. Отсутствующие исходники или тестовые данные должны быть явно обозначены как ограничения.

В карточке интервью есть «Решения раунда · отдельные проверки»: видны тип версии, статус тестов, индивидуальный разбор, сохранённый исходник и перевод комментариев на русский. Частичные результаты сохраняются, даже если общий разбор не завершён. Количество последовательных обращений в Codex зависит от числа артефактов и расходует лимиты аккаунта.

Для запуска нужен работающий и авторизованный Codex-мост и разрешение передачи данных в его настройках. После обновления исходников: обновить страницу и выполнить `make bridge-restart`. Дополнительная сборка контейнеров не требуется. Новые таблицы SQLite создаются при запуске API без удаления существующего прогресса.
