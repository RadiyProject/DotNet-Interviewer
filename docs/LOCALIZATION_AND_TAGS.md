# Локализация и теги

## Данные

- `trainer/content/tasks.json` — канонический банк и стабильные ID тегов в `tags`.
- `trainer/content/tags.json` — единый справочник тегов с подписями `ru`/`en`.
- `trainer/content/tasks.en.json` — английские текстовые поля по ID задания. Не содержит ключей grading, fixtures, correct или harness.
- `trainer/content/translations.en.json` — локальный серверный словарь стандартных сообщений и названий сценариев.
- `trainer/web/locales/en.json` — только подписи интерфейса. Полные переводы ответов не должны попадать в публичный UI-словарь.
- `trainer/web/resources.json` / `resources.en.json` — библиотека на двух языках.

Всего 18 тегов; теги домена (Fintech, E-commerce и другие) комбинируются с тегами навыков (Concurrency, Testing и другие). Это контекст упражнения, а не классификация работодателя. В практике фильтр сочетается с поиском, темой и engine. В теории tag filter ограничивает список тем и вопросов; вход в полный связанный тематический тест сбрасывает этот фильтр.

## Поведение

Язык хранится в `localStorage['forge-language']`. Клиент передаёт `X-Forge-Language: en` в API; без заголовка сервер использует русский. Source of truth для проверки — прежние ID, индексы ответов, reference и harness. Общая история не делится по языку. При смене языка текущий draft сохраняется, затем перезагружается страница с прежним маршрутом и фильтром; время попытки продолжается.

Сервер применяет английский overlay до формирования public task и объяснения. Исторический quiz feedback получает тексты вариантов текущего языка по тем же индексам. Пользовательские `code` и `drafts` не переводятся. Runtime не зависит от сети или сервиса перевода.

UI-словарь локализует отрисованные текстовые узлы и доступные подписи, не меняя значения DOM-атрибутов `value`, ID, обработчики и canonical categories. Редакторы, code/pre и пользовательский код исключены из автоматической DOM-локализации. Системный confirm сброса кода локализуется явно. Даты истории используют выбранную локаль.

## Как расширять

1. Добавь упражнение в `tasks.json` с существующими или новыми зарегистрированными tag IDs.
2. Добавь тот же ID в `tasks.en.json` и переведи текстовые поля: title, desc, kind, requirements, cases, hints, review, answer, choices при наличии, starter, source label и references labels. Сохраняй порядок и длину массивов.
3. Код в starter меняй только в комментариях. Сигнатуры, литералы, SQL-контракт и имена моделей должны совпадать с исходной версией. Не переводить placeholders или данные, которые ожидает harness.
4. Для новых UI-подписей добавь фразу в `web/locales/en.json`; для серверных сообщений — в `content/translations.en.json`. Сообщение с динамическими значениями требует перевода статических фрагментов.
5. Новые материалы библиотеки добавляй в обе версии resources. Сохраняй одинаковые ссылки.
6. При добавлении нового тега заполни обе подписи. Category остаётся канонической для логики группировки; её UI-перевод задаётся словарём.

English API явно сообщает об отсутствии overlay нового задания вместо молчаливого показа смешанного банка. Переводы подготовлены автоматически с выборочной технической редактурой. Произвольный вывод пользовательского кода, compiler diagnostics и значения строковых литералов не обещаются на выбранном языке.

## Выполненная статическая проверка

322 задания имеют теги и английские overlays; все tag IDs зарегистрированы. Число choices/requirements/cases/hints/review совпадает, correct и engine не менялись. У исполняемых заготовок код вне комментариев совпадает. Проверен синтаксис JS/Python без запуска приложения, сборки и тестов. Проверка отображения в браузере в этой работе не выполнялась по инструкции не запускать приложение и его тесты.
