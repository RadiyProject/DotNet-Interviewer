## Как использовать

Порядок для подготовки после разобранного интервью: A82 → A86 → A88 → A89 → A83/A84 → A85 → A87 → A90. Сначала выполнить попытку без разбора. Затем изменить одно условие: tenant стал горячим, replay пришёл позже retention, регион потерял quorum или внешняя операция дала timeout.

Сильный ответ должен содержать:

- явно принятые требования и единицы расчётов;
- API, данные, ключевые ограничения и путь одной операции;
- границу атомарности, владельца данных и поведение при неизвестном исходе;
- одну рабочую альтернативу с ценой, а не перечень технологий;
- деградацию, бюджет ресурсов, метрики и критерий следующего шага масштабирования.

## Техническая редактура и проверки

Сценарии не предполагают, что read replica увеличивает write capacity, consistent hashing делит один горячий ключ, TTL обеспечивает авторизацию или async replication гарантирует RPO=0. У поиска отдельно разобраны delete tombstones и поздний replay; у upload — неоднозначный complete и отличие checksum от multipart ETag; у gateway — перемножение вложенных retry budgets.

Проведена только статическая сверка JSON, текстовых overlays, tag/related ID и временных бюджетов сценариев. Сборка, приложение и его тесты не запускались по инструкции пользователя.
