# DotNet Interviewer

[English guide](README.en.md)

Локальный тренажёр для подготовки к техническим собеседованиям по C#/.NET, базам данных, архитектуре и эксплуатации. Подходит для самостоятельной подготовки к интервью у разных работодателей.

## Запуск

Нужен Docker с Compose v2 и запущенный Docker Engine / Docker Desktop. Только при первом запуске, если локальных образов ещё нет, выполни в папке проекта:

```sh
docker compose up --build -d
```

Открой [http://localhost:8080](http://localhost:8080). Первый запуск скачивает базовые образы и пакеты, поэтому требует интернета. Выполнение решений происходит без сети. Для комфортной компиляции выдели Docker минимум 3 ГБ RAM. Исходники `trainer/` подключены к контейнеру read-only напрямую из рабочей папки. Изменения обычных файлов больше не требуют пересборки образов.

### Переход с уже работающей версии

Если образы уже собраны, один раз пересоздай только app с новым подключением папки (без сборки и перезапуска зависимостей):

```sh
docker compose up -d --no-build --no-deps --force-recreate app
```

Прогресс в volume сохраняется. Последующие обычные запуски:

```sh
docker compose up -d --no-build
```

### Что делать после изменений

| Что изменилось | Что требуется |
|---|---|
| HTML, JavaScript, CSS, vendor-файлы | Обновить страницу браузера |
| `content/tasks.json`, материалы | Обновить страницу браузера |
| `harness/*.cs` | Следующая проверка использует новый файл |
| `runner/runner.py` | Следующая проверка использует новый executor |
| `server.py` и другие Python-файлы верхнего уровня `trainer/` | API автоматически перезапускается примерно через секунду |
| `compose.yaml` | `docker compose up -d --no-build` для пересоздания изменённых сервисов |
| Dockerfile, версия .NET/Python, системные пакеты | Пересобрать соответствующий образ |

API перезапускается стандартным Python supervisor (`trainer/dev.py`) без установки дополнительных библиотек. Если сохранённый Python содержит ошибку и API не стартовал, исправь файл: supervisor увидит новое сохранение и запустит его повторно. Изменение серверного кода во время проверки может прервать HTTP-запрос; после перезапуска такую проверку можно повторить, дедлайн остаётся прежним.

Для ручного перезапуска API без сборки: `docker compose restart app`. `--no-build` не запускает сборку; обычные правки не требуют скачивания базовых образов и установки пакетов. Временная компиляция решения C# при нажатии «Проверить код» остаётся частью самой проверки.

```sh
docker compose logs app
docker compose down
```

Обычный `down` сохраняет прогресс. **`docker compose down -v` удаляет volume с историей.** Перед этим сделай экспорт в интерфейсе.

Сборка приложения, контейнеров и запуск тестов при подготовке этой версии не выполнялись по инструкции пользователя. Первый запуск и проверка в твоём окружении остаются необходимыми. Включённые harness-тесты — часть продукта, а не заявление об успешно пройденной проверке реализации.

## Что есть

334 упражнения:

- **49 C#/.NET** с компиляцией и исполняемыми проверками: HttpClient, статусы/retry/disposal, LINQ, алгоритмы, async concurrency, cancellation, resource ownership.
- **42 SQL**: 18 постановок отдельно для PostgreSQL и SQLite плюс 6 специализированных задач PostgreSQL, каждая на четырёх независимых наборах данных. Границы месяца, одинаковые имена, отсутствие заказов, ties, оконные функции, anti join и LEFT JOIN.
- **172 вопроса** с одиночным или множественным выбором, объяснением и первоисточником.
- **71 задание с рубрикой**: review/implementation, design и инфраструктурные сценарии. Для них есть письменные разборы; результат отмечен как самооценка.

В верхнем меню и на странице обзора явно разделены:

- **Практика** — 91 исполняемая задача: 49 C# и 42 SQL. Группы: LINQ, HTTP, concurrency, ресурсы, алгоритмы, PostgreSQL, SQLite.
- **Теория** — 172 вопроса по темам. Одиночный выбор обозначен radio, множественный — checkbox. Для множественного выбора нужен точный набор верных ответов; пропуски и лишние отметки дают 0, порядок выбора не важен. После отправки показан разбор каждой отметки.
- **Архитектура и ревью** — 71 письменное задание с рубриками самооценки, также сгруппированных по темам.

В карточках есть блок «Связанные вопросы и задачи»: из теории можно перейти к коду/SQL или разбору и обратно. Это тематические переходы с отдельными попытками и таймерами; общий смешанный экзамен пока не реализован. Переход между разделами не останавливает уже начатую попытку.

Всё взаимодействие — в одном веб-интерфейсе: редактор, результаты сценариев, история исходников, таймеры, материалы, рекомендации, карта тем, экспорт/импорт. Никакие ключи LLM или платные API не нужны. Расширение на 73 задания от 24 октября 2026 описано в [BANK_UPDATE_20261024](docs/BANK_UPDATE_20261024.md).

В редакторе C# и SQL добавлены подсветка синтаксиса в палитре VS Code Dark+, номера строк и горизонтальная прокрутка. Сохранённые решения в истории также подсвечиваются. Prism 1.30.0 поставляется локально с MIT-лицензией в `trainer/web/vendor/prism`: CDN и интернет для подсветки не нужны. Это синтаксическая подсветка, без Roslyn/IntelliSense и семантического анализа VS Code.

### Проверить код перед отправкой

После «Начать попытку» в исполняемой задаче доступна кнопка **«Проверить код»**. Она запускает тот же harness или SQL fixtures, показывает ошибки компиляции, результаты сценариев и вывод `Console.WriteLine`, но не завершает попытку и не записывает пробный балл в аналитику. Можно исправлять код и повторять проверку до дедлайна; таймер продолжает идти и во время пробного запуска. Проверяется снимок исходника на момент нажатия кнопки.

**«Отправить решение»** отдельно запускает окончательную проверку, завершает попытку и сохраняет результат в истории. C# проверяется исполнением, SQL — значениями результата на наборах данных. Текст исходника и способ реализации с эталоном не сравниваются: допустимы разные решения, соблюдающие сигнатуры, поведение, порядок результата и прочие условия контракта. Успех на конечном наборе сценариев не является доказательством корректности на всех возможных входах; сложность и качество архитектуры требуют отдельного анализа.

C# исполняется на .NET 10. Встроены BCL и shared framework Microsoft.AspNetCore.App. NuGet sources отключены в песочнице; пользовательское решение не скачивает пакеты. Для задач с зависимостями они автоматически заранее восстанавливаются отдельным контейнером в общий volume `interview-lab-nuget`, затем подключаются к исполнителю read-only. Версии задаются в `trainer/content/packages.json`; новые версии не требуют rebuild image. Первый restore требует интернета и может занять несколько минут; далее используется кеш. Загрузка зависимостей не запускалась при подготовке этой версии. PostgreSQL устанавливается из Debian-пакетов runner-образа; точная версия определяется базовым образом. SQLite — из Python stdlib. Версии можно зафиксировать digest-ами образов и репозиторием пакетов для строгой воспроизводимости.

EF Core + SQLite и Dapper проверяются реальным исполнением в C24–C26. Azure, Kubernetes, brokers, security и AI engineering покрыты теорией, задачами и рубриками. Облачные среды, настоящий AKS и брокер в Compose не разворачиваются. Запуск произвольных solution/csproj с пользовательскими зависимостями и выполнение T-SQL пока не реализованы; дополнительные разрешённые пакеты задаются доверенной конфигурацией банка. Нельзя выдавать проверку SQLite за проверку SQL Server.

## Попытки и аналитика

1. Выбери задачу и нажми «Начать попытку». До старта условие доступно для ознакомления.
2. Сервер сохраняет начало и дедлайн. Паузы нет: закрытие вкладки, переход к другой задаче и перезапуск браузера не останавливают время.
3. Отправка до дедлайна фиксирует время решения; компиляция не отнимает тренировочные минуты. После дедлайна код сохраняется с результатом «Время истекло». При открытой задаче отправка происходит автоматически; при закрытой странице просрочка применяется при следующем открытии/отправке.
4. Разбор можно открыть во время попытки. Тогда она считается учебной и не повышает независимый показатель.
5. После завершения можно начать новую попытку. Кнопка не очищает предыдущий черновик: для повторения с нуля замени редактор заготовкой или сотри решение.

Баллы C# — доля пройденных сценариев; SQL — доля совпавших fixture-наборов; теория — 0/100. Не измеряются автоматически asymptotic complexity, качество архитектуры, стиль кода, английский или seniority. Частичный успех сценариев не доказывает полную корректность. Проверки открыты в репозитории и подходят для честной самоподготовки, а не сертификации.

Показатель задачи: среднее последних трёх самостоятельных проверок. «Закреплено»: среднее ≥85% и минимум два успеха с интервалом ≥24 ч. Покрытие темы всегда показывается отдельно от среднего результата проверенной части. Самооценки, попытки с разбором и импортированная история не входят в независимую оценку. Рекомендации используют приоритет, ошибки и давность повторения; это прозрачная эвристика, не AI-диагностика.

Черновики сохраняются на сервере с задержкой 550 мс. В браузере дополнительно есть аварийная копия текста и кнопка восстановления при несовпадении. На истории хранится именно отправленный исходник. Экспорт включает черновики и завершённые попытки. Импорт объединяет историю по ID, не восстанавливает активные экзамены. Из экспорта старой HTML версии v2 переносятся черновики, но не галочки «завершено» как проверенный результат.

## Устройство и расширение

```text
compose.yaml                 локальный API и сборка runner image
trainer/server.py            HTTP API, SQLite, дедлайны, orchestration
trainer/dev.py               автоматический перезапуск API при сохранении Python
trainer/web/                 интерфейс без npm и внешних CDN
trainer/content/tasks.json   расширяемая база заданий
trainer/harness/*.cs         исполняемые C# проверки
trainer/runner/               эфемерная песочница C#/PostgreSQL/SQLite
docs/CONTENT_GUIDE.md         формат и правила добавления заданий
docs/PREPARATION_MAP.md       направления подготовки и порядок занятий
docs/SOURCES.md               происхождение материалов и литература
```

Контент, harness и доверенный исходник executor runner.py загружаются с диска при обращении. Executor передаётся в одноразовый контейнер через stdin вместе с payload; исходники не монтируются в песочницу и ей не открывается доступ к рабочей папке. После правок базы обнови страницу. Сохраняй ID существующих заданий: это ключ истории. Для принципиально нового контракта создай новый ID. Новые типы runner требуют изменения executor, allowlist и интерфейса; одного JSON недостаточно. Подробнее — в CONTENT_GUIDE.

## Данные и границы песочницы

SQLite с прогрессом хранится в именованном volume `progress`. Зависимости отдельно кешируются в `interview-lab-nuget`; `down -v` удаляет оба volume. Исполняемые задания не получают этот volume, исходники проекта или Docker socket. Каждая проверка создаёт новый контейнер без сети, без capabilities, под UID 10001, с read-only root, tmpfs, лимитами CPU/RAM/PIDs/output. Лимит API — 75 секунд, watchdog внутри runner — 65 секунд, одна проверка одновременно. После проверки контейнер удаляется. Ошибки запуска образа возвращают попытку в активное состояние и не считаются неверным решением; дедлайн при этом не продлевается.

**Это личный локальный тренажёр.** API-контейнер управляет контейнерами через `/var/run/docker.sock`, что даёт ему широкие права на Docker daemon. Порт привязан к loopback, запросы ограничены локальными Host и same-origin JSON. Не публикуй сервис в интернет и не принимай через него чужой недоверенный код. Для multi-user сервиса потребуется отдельный runner host/VM, аутентификация, очередь и более сильная изоляция. Контейнер не является гарантированной границей против целевой эксплуатации ядра.

Если процесс API аварийно завершился, runner самостоятельно заканчивает работу по watchdog. Проверку, оставшуюся в состоянии checking, API возвращает в активную при запуске. Для диагностики оставшихся контейнеров используй `docker ps -a --filter name=interview-lab-`; не удаляй контейнеры другого проекта.

Источники могут открываться во внешнем браузере по ссылке; сам код никуда, кроме локального Docker, не отправляется.

### Окружение SDK и редактор (27.10.2026)

API передаёт `runner/environment.py` перед executor/restore: HOME, DOTNET_CLI_HOME и XDG-каталоги расположены в writable `/work/.sdk-state`, runtime-каталог имеет права 0700. Это нужно в том числе для named mutex NuGet-Migrations в новых .NET runtimes; одного DOTNET_CLI_HOME недостаточно. NuGet volume по-прежнему подключается к исполнению read-only. Правка применяется к следующей проверке без пересборки образа.

Ошибки SDK/restore без диагностики C# `error CSxxxx` возвращаются как ошибка окружения, а не ошибка компиляции решения. Такие отправки не завершают попытку и не попадают в оценки; таймер попытки продолжает идти. Уже записанная история автоматически не переписывается.

Редактор: Tab вставляет пробелы до следующей позиции в 4 колонки; для выделения сдвигает все затронутые строки. Shift+Tab убирает один уровень, Enter сохраняет текущий отступ, без автоматического увеличения вложенности и дополнительных строк между скобками. Backspace в начальных пробелах убирает отступ до предыдущей позиции в 4 колонки. Esc, затем Tab позволяет перейти к следующему элементу интерфейса. Автосохранение и подсветка используют общий input-поток. Это базовое редактирование текста, без семантического форматтера C#.

### Implicit usings как в ASP.NET Core

В C# runner включены стандартные implicit usings .NET SDK и дополнительные пространства имён Web SDK: System.Net.Http.Json, Microsoft.AspNetCore.Builder/Hosting/Http/Routing, Microsoft.Extensions.Configuration/DependencyInjection/Hosting/Logging. Они добавлены через MSBuild Using items при сохранении console harness. Поэтому ReadFromJsonAsync доступен без отдельного using; shared framework уже подключён, новые пакеты не скачиваются. Это не импорт всех библиотек: например, System.Net (HttpStatusCode), System.Text.Json и EF Core требуют явного using. Основание: https://learn.microsoft.com/en-us/dotnet/core/project-sdk/overview#implicit-using-directives . Правка применяется при следующей проверке без Docker build; сборка и тесты при подготовке не запускались.

### Теоретические тесты по темам

Раздел теории имеет отдельную компоновку: выбор укрупнённой темы, список только её вопросов и единая карточка вопроса с вариантами ответа, таймером и отправкой. Кнопки «Назад / Далее» расположены сверху и снизу карточки. Связанные задания содержат вход «Тест по теме» со всеми вопросами выбранной темы; он открывает первый ещё не пройденный вопрос. Родственные категории объединяются только для этой навигации; ID, содержание и история сохраняются. Прогресс темы показывает успешные последние сохранённые ответы, включая учебные; для самостоятельного освоения остаются отдельные статусы вопросов. Это последовательный тематический тест с индивидуальными таймерами, без общего экзаменационного дедлайна. Ответ отправляется отдельно на каждом вопросе; переход не завершает активную попытку.

Проверен синтаксис изменённых JavaScript-файлов (`node --check`), без запуска приложения, сборки и тестов.

### Настоящий ChatGPT Voice

Добавлено локальное расширение Chrome/Edge для связки конкретной вкладки ChatGPT с интервью: передача контекста/кода, очередь обновлений и сохранение видимой расшифровки. Сам голос работает в ChatGPT, итоговый разбор — через Codex CLI. Есть также сценарий для встроенного голоса Codex/Work и ручной импорт диалога. [Установка и ограничения](docs/CHATGPT_VOICE.md).

Привязка расширения ChatGPT теперь получает токен автоматически из открытого интервью через localhost (включая Safari → Chrome). Подтверди запрос на странице раунда и вернись в расширение. Ручной ввод остаётся запасным вариантом. Токен Codex-моста по-прежнему берётся из терминала.

PDF-резюме можно загрузить непосредственно в форме профиля: текст извлекается в браузере без Codex-моста и токенов. До 2 МБ, 30 страниц и 50 000 символов. Для сканов нужен предварительный OCR; результат можно исправить перед сохранением. Пересборка Docker для этого изменения не нужна.

Создание AI-раунда теперь означает подготовку без расхода времени. Подключи ассистента и нажми «Начать интервью» на странице или в расширении — только тогда стартует серверный таймер.

### Разбор через Codex CLI

Запусти `python3 tools/ai_bridge.py` на компьютере с установленным и авторизованным Codex CLI. Вставь Pairing token в карточку Codex на сайте и разреши передачу выбранных материалов. Подключение проверяется автоматически. Это отдельный токен от расширения ChatGPT.

После выхода из Voice заверши раунд через расширение: оно сохраняет расшифровку и завершает тот же раунд на сервере. Сайт обновляет состояние при открытой вкладке или сразу после возвращения к ней. Ошибка чтения чата не мешает остановить таймер: сайт покажет неполную расшифровку и предложит синхронизацию или ручной импорт до AI-оценки.

AI-разбор выполняется фоновым заданием моста. Обновление страницы не перезапускает CLI; при возвращении в завершённый раунд известное задание подхватывается автоматически. Ошибка остаётся под кнопкой разбора. Готовый результат фиксируется в серверной истории. До фиксации результаты заданий хранятся только в памяти моста до часа (не более 20 заданий): перезапуск самого моста их удаляет и меняет Pairing token. Скачивание JSON — отдельный экспорт, оно не запускает Codex.

Async TTL-кэш и защита от stampede: C47, Q165–Q172, A52–A54. [Карта нового материала и границы проверок](docs/ASYNC_CACHE_PACK.md).
