# DotNet Interviewer

Локальный тренажёр для подготовки к собеседованиям C#/.NET-разработчика: практика C# и SQL с исполняемыми проверками, теория, архитектура, конструктор собеседований и AI-интервью. Есть таймеры, история, аналитика, ревью кода и переводы AI-ответов на русский.

**ChatGPT Voice проводит голосовой разговор, Codex CLI проверяет код и готовит итоговый разбор.** Обычные задания работают без AI. Интерфейс и банк доступны на русском и английском.

## Установка и запуск

Нужны запущенный Docker Desktop / Docker Engine с Compose v2 и команда `make`. Для голоса дополнительно нужны Chrome или Edge, микрофон и аккаунт ChatGPT с доступным Voice. Сайт можно открывать в Safari. .NET SDK и Codex CLI на компьютере устанавливать не требуется: они находятся в контейнерах.

Из папки проекта:

```sh
make setup        # первый запуск: собрать образы и запустить контейнеры
make codex-login  # один раз авторизовать Codex внутри контейнера
```

Для входа Codex покажет адрес и код: открой адрес в браузере и подтверди вход своим аккаунтом. Авторизация сохраняется между перезапусками. В тренажёре открой настройки Codex CLI, проверь подключение и разреши передачу выбранных материалов. Технический токен моста сайт получает автоматически.

Открой **[localhost:8080](http://localhost:8080)**. Первый запуск и восстановление новых NuGet-зависимостей требуют интернета.

## Практика и проверки

Выбери задачу → прочитай контракт → начни попытку → напиши решение → проверь → отправь до дедлайна. Пробная проверка не заменяет отправку решения. Архитектурные задания используют письменные ответы и рубрики самооценки.

«Качество решения» содержит статический анализ и ревью Codex CLI. Сохранённые ревью, подсказки и исходный вариант кода доступны позже. «Показать по-русски» сохраняет перевод рядом с оригиналом. Конструктор собирает набор заданий по темам, тегам и времени для самостоятельного прохождения или AI-раунда.

## Code review: самостоятельно, с текстовым и голосовым ассистентом

В **«Архитектура и ревью» → тема «Code review»** доступны A55–A67: HTTP/async, EF Core, SQL, кэш, очереди, outbox, ретраи и другие сценарии. Исходный фрагмент с подсветкой показан отдельно от редактора замечаний. Начни попытку, выпиши дефекты с приоритетами и сценариями отказа, предложи минимальные исправления и проверки; затем отправь ревью. Для самостоятельной сверки есть рубрика и разбор.

- **Текстовый режим:** «Оценить моё ревью · Codex CLI» оценивает твои замечания — пропуски, ложные срабатывания, аргументацию и приоритеты. Подсказки, история и русский перевод доступны в том же блоке. Для другого ассистента можно скачать пакет «Внешний AI» и импортировать JSON-ответ.
- **Голосовой режим:** включи задание в план технического или лидского интервью, подключи ChatGPT Voice и нажми в задании «Обсудить моё ревью с интервьюером». Интервьюер получает исходный фрагмент и текст замечаний; можно уточнять требования, защищать решения и обсуждать альтернативы. Следующую версию отправляй повторным нажатием; при скрытом поле ввода Voice доставка может ждать.

Фрагменты намеренно содержат дефекты и автоматически не исполняются. Запрос AI-помощи делает текущую попытку учебной; письменный ответ и AI-фидбек не считаются пройденными функциональными тестами. [Подробный сценарий](docs/CODE_REVIEW.md).

## Расширение и голосовое интервью

1. В Chrome открой `chrome://extensions` (в Edge — `edge://extensions`). Включи **«Режим разработчика» → «Загрузить распакованное»**, выбери папку `tools/chatgpt-companion`. Закрепи расширение **Forge · ChatGPT Voice Companion** и обнови уже открытую вкладку ChatGPT.
2. Во вкладке **AI-интервью** сохрани профиль, добавь резюме и сведения об опыте. Выбери этап, язык, длительность и ассистента **ChatGPT Voice**, затем подготовь раунд. Таймер пока не идёт.
3. В расширении нажми **«Подключить открытое интервью»**, на сайте подтверди **«Подключить расширение»**. Токен передастся автоматически. Открой отдельный чат ChatGPT и свяжи его с этим раундом кнопкой расширения.
4. Разреши передачу данных, нажми **«Передать контекст в ChatGPT»** и дождись подтверждения доставки. Для одного раунда используй один чат.
5. **Самостоятельно запусти голосовой разговор в ChatGPT**, разреши микрофон и проверь связь. Затем нажми **«Начать интервью»** на сайте или в расширении. Если сообщение о старте осталось в поле ChatGPT, отправь его вручную.
6. Во время технического раунда решай задания в тренажёре. **«Показать вариант кода»** передаёт текущий C# или SQL интервьюеру текстом; следующую версию отправляй повторным нажатием. Отправленный результат тестов приложи к раунду. Если Voice скрывает поле ввода, обновление контекста может ждать выхода из голоса.
7. Для досрочного завершения выйди из Voice, дождись расшифровки и нажми в расширении **«Завершить и передать на разбор Codex CLI»**. Открой раунд на сайте: сводка запускается автоматически при включённой опции и настроенном Codex либо кнопкой **«Получить сводку Codex CLI»**.

По дедлайну расширение сохраняет доступный диалог и завершает раунд, не обрывая Voice. После выхода из голоса оно досохраняет расшифровку. Оставляй Chrome, связанный чат и расширение включёнными. Переводы голосовых реплик доступны в тренажёре после синхронизации.

Голос использует интерфейс ChatGPT, отдельный API-ключ не нужен. Это автоматизация страницы, поэтому изменения ChatGPT могут потребовать обновления расширения. Резюме, код и переписка отправляются в AI только при разрешённой передаче; действуют лимиты аккаунтов.

## Повседневные команды

| Команда | Действие |
|---|---|
| `make` | Список команд |
| `make up` / `make down` | Запустить без сборки / остановить с сохранением данных |
| `make status` / `make logs` | Состояние контейнеров / логи |
| `make codex-status` | Проверить вход Codex |
| `make bridge-restart` / `make bridge-logs` | Перезапустить мост / посмотреть его логи |
| `make restart` | Перезапустить приложение |

Обычные изменения кода и заданий не требуют пересборки образов. После изменения кода моста выполни `make bridge-restart`; после изменения расширения — «Перезагрузить» на странице расширений и обнови ChatGPT. Dockerfile и системные зависимости требуют сборки: `make setup` для проекта или `docker compose up -d --build ai-bridge` только для моста.

Данные хранятся в Docker volumes: прогресс — `progress`, авторизация Codex — `codex-auth`, NuGet — `nuget`. **`docker compose down -v` удаляет эти данные.** Git сохраняет исходники, но не volumes: для сохранности результатов используй экспорт в интерфейсе. Проект рассчитан на локальное использование, API имеет доступ к Docker socket.
